# Verified Agent Communication

When you need to send a verified message to another agent or verify that a response is authentic, use this tool. It prevents hallucinated responses by requiring request_id round-trip verification.

## Usage

### Send a message
```bash
ath verify --send --to "http://localhost:8004/talk" --message "What is 2+2?"
```

### Verify a response
```bash
ath verify --check --request-id "abc-123-uuid" --response '{"request_id": "abc-123-uuid", "response": "4"}'
```

## Flags

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--send` | One of send/check | — | Send mode |
| `--check` | One of send/check | — | Check mode |
| `--to` | With --send | — | Target agent URL |
| `--message` | With --send | — | Message to send |
| `--request-id` | With --check | — | Expected request ID |
| `--response` | With --check | — | Response text to verify |
| `--timeout` | No | 10000 | Timeout in milliseconds |

## Output

### Send mode
```json
{
  "status": "ok",
  "data": {
    "status": "verified",
    "response": "4",
    "source": "math-agent",
    "request_id": "abc-123-uuid",
    "latency_ms": 42.3
  }
}
```

### Check mode
```json
{
  "status": "ok",
  "data": {
    "verified": true,
    "request_id": "abc-123-uuid"
  }
}
```

## Requirements

- Install: `pip install cli-tools-hub`
- Target agent must accept POST with `{"request_id": "...", "message": "..."}` and echo back the `request_id`

## When to use

- Sending a message to another agent and needing to verify the response is real
- Checking if a response was actually generated by the agent you contacted
- Preventing hallucinated or spoofed agent responses

## When NOT to use

- Simple HTTP requests that don't need verification
- Communication with APIs that don't support request_id echo
- When you just need to call a REST API (use curl or requests instead)
